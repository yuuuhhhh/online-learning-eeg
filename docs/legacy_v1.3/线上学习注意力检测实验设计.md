# 线上学习 EEG 实验设计：v2.1 第四阶段范式骨架

## 1. 当前实现范围

当前版本用于开发/pilot 前调试，目标是验证“视频观看 + B 条件脑内连续减7 + thought probe + probe 前 10 秒 EEG 定位”的主流程、事件记录和数据字段。它还不是正式实验版本。

第三阶段实现了 thought probe 第一问、confidence 第二问和 probe 期间的视频暂停/恢复。第四阶段在此基础上增加 probe 前 10 秒 EEG epoch 定位、4 秒/2 秒窗口索引、NONE 标签和分析友好的 CSV/MAT 输出。

本阶段仍不包含 self-caught、G01–G12 平衡分组、新问卷、新课堂题或正式实验严格状态机。

## 2. 条件定义

### A 条件

- `condition_label=A`
- `condition_type=focused`
- 指导语：“像正常线上学习一样认真观看，尽量理解和记忆，结束后有课堂理解题。”

### B 条件

- `condition_label=B`
- `condition_type=bbbd_subtraction`
- 指导语：“视频继续播放，从屏幕给出的数字开始在脑中连续减7；不出声、不持续输入；视频开始后数字消失。”

A/B 是 Block 级实验条件，不能解释为被试某一时刻的注意力真值。本阶段所有 EEG 的 `weak_label=-1`，未来由 thought probe 产生瞬时标签。

## 3. 连续减7练习

正式 Block 前显示一次简单练习：

> 从给定数字开始，在脑中连续减7。不出声，不使用手指明显计数，不持续按键。

当前练习数字为 100。实验员或测试人员点击“已理解，可以继续”后进入后续流程。记录：

- `subtraction_practice_start`
- `subtraction_practice_end`
- `practice_confirmed`

练习期 EEG 使用 `phase=subtraction_practice` 和 `is_formal_experiment=0`，不归属任何正式 Block 或 A/B 条件。

## 4. B 条件起始数字

会话建立时，为本次顺序中的三个 B Block 预生成三个不同的素数。范围包含 800 和 1000 的边界判断，实际候选只取该闭区间内的素数。

每个 B Block 的数字保存在 `metadata.json` 的 `session.b_start_numbers`，包含：

- `start_number`
- `generated_timestamp`
- 对应的 `block_id`

Block 开始提示时醒目显示数字并记录 `subtraction_start_number_displayed`。浏览器确认视频实际播放后立即隐藏数字并记录 `subtraction_start_number_hidden`。事件行同时保存生成、显示和隐藏时间以及条件信息。

## 5. Block 流程

当前仍沿用开发版顺序 1/2：

- 顺序 1：A-B-A-B-A-B
- 顺序 2：B-A-B-A-B-A

每个 Block 的流程为：

1. 显示条件指导语；B 条件同时显示起始数字。同时生成本 Block 的 thought probe 时间表。
2. 视频开始，记录 `video_start`/`video_play`；B 数字立即隐藏。
3. 视频播放期间不要求持续键盘或鼠标输入；到达 probe 时间时自动暂停并提问。
4. 视频结束后完成已有课程注意力评分和课堂理解题。
5. Block 1–5 进入休息；Block 6 结束。

新会话不会生成随机算式、题目显示/空白计时、按键判断或旧算术事件。历史 CSV 中的相关事件仍由 MAT 导出器原样兼容读取。

## 5.1 thought probe

每个 Block 在视频开始前生成一份 probe 时间表，保存在 `metadata.json` 的 `session.probe_schedules[block_id]`，并由 `probe_schedule` 事件记录。默认配置 `session.probe_config` 为：

| 参数 | 默认值 |
|---|---:|
| `probes_per_block` | 4 |
| `min_first_onset_sec` | 45 |
| `min_end_margin_sec` | 30 |
| `min_gap_sec` | 45 |

时间表在 `[45, 时长-30]` 区间内随机抽取，并保证相邻间隔不小于 45 秒，因此不同 session 不会使用同一组固定时点。视频过短时只生成能满足约束的数量，绝不压缩间隔。采集端会按声明的配置复核每一份时间表，不满足约束的时间表被拒绝。

probe 依据 `video.currentTime` 触发，不使用墙钟；视频暂停时 `currentTime` 不前进，因此暂停期间不会推进到下一个 probe。probe 呈现期间视频保持暂停，浏览器会拦截任何在作答完成前恢复播放的尝试。

第一问对 A/B 条件使用同一组选项，必须作答后才会显示 confidence：

| 选项 | 文本 | `probe_attention` |
|---:|---|---|
| 1 | 课程内容 | ON |
| 2 | 连续减7心算任务 | OFF |
| 3 | 其他与课程无关的事情 | OFF |
| 4 | 放空/不确定刚才在想什么 | AMBIGUOUS |

回答按原样保存。A 条件下选择“连续减7心算任务”同样记录为 `OFF`，程序不会依据当前条件自动纠正。

第二问为 1～4 分的确定程度，同样必须作答。提交后隐藏 probe 界面、从原位置恢复播放，并记录 `pause_reason=thought_probe` 的 `video_resume`。

每个 probe 形成固定事件链 `probe_onset → attention_response → confidence_response → video_resume`。采集端按 `probe_id` 校验顺序，跳步或重复的事件会被拒绝。probe 期间 EEG 的 `phase=thought_probe`、`is_formal_experiment=0`、`weak_label=-1`。

## 5.2 probe 前 10 秒 EEG epoch 与窗口索引

每个 probe 的 `probe_onset` 事件带有一个由第一阶段事件定位机制得到的 `device_sample_number`。以该样本号为终点向前取固定 10 秒 EEG，即 250 Hz 下的 2500 个样本，区间为 `[onset - 2500, onset - 1]`。终点取 onset 前一个样本，保证整段 10 秒完全位于 probe 页面出现之前，不含任何作答期间的 EEG。定位只使用真实 `device_sample_number`，不使用 `probe_planned_time_sec`。

出现下列任一情况时该 epoch 记为 `rejected` 并写明原因，不做任何补齐或外推：

| reject_reason | 含义 |
|---|---|
| `incomplete_probe_chain` | 缺少 attention 或 confidence 作答，或该 probe 被取消 |
| `probe_onset_not_aligned` | `probe_onset` 没有对齐到 EEG 样本 |
| `insufficient_history` | probe 之前不足 10 秒 EEG |
| `incomplete_eeg` | 10 秒内有丢包、重复样本或跨 `stream_segment` |
| `overlaps_probe_page` | 10 秒与任一 probe 页面区间重叠 |

每个有效 epoch 按 4 秒长度、2 秒步长切成 4 个窗口。窗口只记录样本索引和标签，不复制 EEG 波形；原始 EEG 仍只在 `eeg.csv` 与 `eeg_raw.bin` 中保存一份。`seconds_to_probe` 为窗口结束到 probe onset 的秒数，四个窗口依次为 6、4、2、0。同一 probe 的全部窗口共用同一个 `probe_id`，训练集划分必须按 `probe_id` 整组切分。

`probe_attention` 只允许 ON、OFF、AMBIGUOUS、NONE 四个取值。probe 确认的 10 秒区域使用 ON/OFF/AMBIGUOUS；视频中没有被任何 probe 问到的普通区域，若需要条件数据窗口，一律标为 NONE，不会被自动当成 ON 或 OFF。A/B 仍然只是条件弱标签。

窗口的 `quality_label` 为 `good`、`warning` 或 `reject`。命中以下任一情况即为 `reject`，并在 `reject_reason` 中累计：EEG 质量标记非 `ok`（`eeg_quality_flag`）、覆盖非正式阶段样本（`non_formal_phase`）、与现有 QC 的 `bad` 窗口在时间上重叠（`qc_reject`）。本阶段直接使用现有 QC 结果，没有重新设计 QC 体系。

## 5.3 50 Hz 工频干扰的处理

50 Hz 工频干扰可以在分析阶段用陷波去掉，所以采集阶段只测量和提示，不据此丢弃数据。`line_50hz_ratio_pct` 仍然按 48–52 Hz 相对 1–100 Hz 的功率比逐通道计算并写入 `qc.csv`，超过阈值时页面照常提示，但 QC 状态最多为 `warning`，不再变成 `bad`，采前基线也不会仅因为 50 Hz 偏高而判为不通过。

对应的显式标志为 `warning_50hz` 和 `needs_notch`，同时出现在 QC 快照、`qc.csv` 和 `windows.csv` 中。窗口如果唯一的问题就是 50 Hz 偏高，`quality_label` 记为 `warning` 而不是 `reject`，`reject_reason` 为空，数据仍然可用。

以下情况仍然是 `reject`，50 Hz 标志不会把它们救回来：EEG 缺失或不完整、平线、饱和、设备掉线、样本不连续、明确的严重运动伪迹、probe epoch 不完整。

采集阶段不会对原始 EEG 做任何滤波，也不会覆盖原始数据。50 Hz 陷波和随后的 analysis QC 都在分析阶段对原始 EEG 的副本进行。当前阈值和 analysis QC 规则是暂定的，等 pilot 之后再冻结。

## 6. 休息流程

| 完成的 Block | 计划休息时间 |
|---|---:|
| 1 | 30 秒 |
| 2 | 30 秒 |
| 3 | 180 秒 |
| 4 | 30 秒 |
| 5 | 30 秒 |
| 6 | 结束 |

休息记录 `rest_start`、`rest_end`、`after_block_id`、`planned_duration` 和 `actual_duration`。开发调试时允许提前结束倒计时，实际经过时间仍写入事件。

## 7. 数据语义

### EEG 行

- `condition`：A、B，非视频阶段为空。
- `condition_type`：`focused` 或 `bbbd_subtraction`，非视频阶段为空。
- `condition_code`：A=0、B=1、非条件阶段=-1。
- `weak_label`：本阶段统一为 -1，不提供瞬时注意力标签。probe 的自我报告不写入 EEG 行。
- `is_formal_experiment`：只有视频阶段为 1；练习、休息、probe 作答和其他阶段为 0。

### 事件行

事件带有 `run_id`、`session_id`、`block_id`、`condition`、`condition_type`、校准后的事件时间、服务器接收时间，以及最近 EEG 行/样本关联。该时间精度仍受浏览器调度、HTTP 和 BLE 接收抖动影响。

第三阶段为所有事件补充了 `video_id`、`condition_label`、`video_time_sec`、`browser_timestamp`、`recorder_timestamp` 和 `device_sample_number`。其中 `browser_timestamp` 是浏览器原始时钟读数、`recorder_timestamp` 是采集端写入时刻、`device_sample_number` 与 `eeg_sample_number` 同源，均由第一阶段的事件定位机制产生，没有另起一套时间系统。

probe 事件另有 `probe_id`、`probe_index`、`probe_schedule_id`、`probe_planned_time_sec`、`response`、`response_label`、`response_time_ms`、`confidence`、`probe_attention` 和 `pause_reason`。

同一主机接收时间戳上的一批 BLE 样本，事件对齐到该批次中最新的样本，避免 onset 锚点整体偏早一个批次。

### 分析文件

会话停止时生成两份派生索引，位于会话目录内，MAT 中同名保存：

- `probe_epochs.csv`：每个 probe 一行，含身份字段、`probe_attention`、`probe_response`、`probe_confidence`、`probe_onset_sample`、`start_sample`、`end_sample`、`start_timestamp`、`end_timestamp`、`sample_count`、`status`、`reject_reason`、`window_count`。
- `windows.csv`：每个 4 秒窗口一行，含 `window_id`、`probe_id`、`window_kind`（`probe_epoch` 或 `condition`）、`window_index`、`seconds_to_probe`、样本与时间边界、`quality_label`、`reject_reason`、`qc_status`、`warning_50hz`、`needs_notch`，以及被试、会话、视频、Block、条件等分组字段。

这两份文件只保存样本索引和标签，不再往 `events.csv` 的 `notes` 里继续堆内容。旧会话没有 probe 事件时不会生成这两份文件，MAT 中也不会出现对应字段，导出流程不受影响。

## 8. 开发阶段保留行为

- 可快速结束休息，不要求等待 30 或 180 秒。
- 可重复选择和调试 Block；重复调试同一 Block 时 `probe_id` 仍然互不重复。
- 可复用测试视频。
- 勾选“调试：快速probe”后改用 5/3/5 秒的调试配置，短测试视频也能连续触发四个 probe；事件与 `metadata.json` 会标记该时间表未使用正式配置。
- “调试：立即触发下一个probe”按钮可在当前播放位置立刻触发下一个 probe，事件带 `forced` 标记。
- 沿用现有采前 QC 和 A/B 顺序校验，没有新增正式采集限制。

## 9. 进入第五阶段前的风险

- self-caught 走神报告尚未接入。
- 每个 Block 最多 4 个 probe，一次会话最多 24 个 10 秒 epoch、96 个窗口，样本量对训练 ON/OFF 分类器仍然偏少。
- `qc_reject` 使用 QC 滚动窗口与窗口时间区间的重叠判定，QC 窗口长度为 10 秒，粒度粗于 4 秒窗口，可能连带否掉相邻的好窗口。`needs_notch` 的传播同理，会把标志扩散到相邻窗口。
- 50 Hz 阈值和 analysis QC 规则仍是暂定值，需要 pilot 数据之后冻结；在此之前 `warning` 窗口是否纳入训练由分析阶段决定。
- 当前没有独立的运动伪迹检测器，严重运动伪迹依赖饱和、平线和 RMS 突变间接捕捉。
- `condition` 类 NONE 窗口按 Block 内连续样本段平铺，窗口之间有 2 秒重叠，直接做统计时需按窗口独立性处理。
- 无响应策略尚未定义：当前第一问和 confidence 都必须作答，没有超时跳过路径，probe 会一直等待被试。
- probe 呈现时点依赖浏览器 `timeupdate` 回调，典型间隔约 250 毫秒，实际 onset 可能略晚于计划时间；分析应使用事件中记录的 `video_time_sec` 而不是 `probe_planned_time_sec`。
- 浏览器事件与 EEG 的关联基于时间校准和最近接收样本，不具备硬件触发器精度。
- 脑内减7没有持续行为输入，本阶段不能从系统记录直接确认执行质量。
- `probe_attention` 来自被试自我报告，不是经过验证的注意力真值；EEG 行的 `weak_label` 仍为 -1。
- G01–G12、视频顺序与条件的正式平衡方案尚未实现。
- 两通道硬件比例尺、参考和物理单位仍需设备方确认。
